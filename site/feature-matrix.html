Which Adapter Do I Actually Get?

You never need to pick an adapter by name to get started — minibox detects your platform and picks a working default. The table below says what that default is, in terms of your operating system rather than internal adapter names.

Your OSWhat minibox uses by defaultWhy
LinuxnativeDirect namespaces/cgroups — the full-featured reference path. No VM, no extra install.
macOSsmolvm, falling back to krunmacOS has no native Linux container primitives, so minibox boots a lightweight Linux VM automatically. Core lifecycle (pull/run/stop/rm/ps) works; exec into a running container and log retrieval don't yet.
macOS, already using Colima for other toolscolima (opt-in: MINIBOX_ADAPTER=colima)Reuses your existing Lima/nerdctl setup instead of a second VM. Same lifecycle coverage as smolvm/krun, plus limited log support.
Linux, inside a GKE podgke (opt-in: MINIBOX_ADAPTER=gke)Unprivileged pod execution via proot and a copy filesystem — no namespace/cgroup isolation, but works where you can't get privileged access.
Windowsnothing yetwinbox is a stub and returns an error unconditionally. Not usable today.

The adapter names in the table below (native, colima, smolvm, krun, vz, winbox) are internal identifiers you'll see in error messages, mbx doctor output, and the MINIBOX_ADAPTER env var — useful once you need to override the default, not something you need to know up front.

Current Limits and Networking

  • Image pulls enforce a 10 MiB manifest limit, 10 GiB per layer, and 50 GiB aggregate.
  • Native networking provides bridge allocation, DNAT port forwarding, and DNS configuration.
  • minibox-cni is available behind the optional CNI feature for native networking.

Control Surfaces

  • mbx: button-primary daemon CLI.
  • minibox-mcp: implemented MCP stdio server; mutations and higher-risk run options require explicit policy enablement.
  • minibox-crux-plugin: JSON-RPC stdio bridge.
  • minibox-tui: optional read-only dashboard exposed through the CLI feature.

Adapter Notes

Native and GKE are production adapters. GKE uses proot and a copy filesystem without native namespace/cgroup isolation.

Colima, smolvm, and krun have partial support: core lifecycle (pull/run/stop/rm/ps/restart) works today and is actively used, but exec into a running container and full log retrieval are not yet implemented on any of them. Colima delegates to Lima/nerdctl; smolvm and krun use lightweight VMs.

VZ source was restored behind the macOS feature. It remains non-functional because VZLinuxBootLoader fails on current macOS before the adapter can serve requests.

Winbox is a stub and returns an error unconditionally.
