Roadmap

Evidence-backed priorities for making the runtime safer, more portable, and easier to operate without obscuring its systems-programming core.

Baseline 0.33.0Active developmentUpdated 2026-09-15

Native Linux runtime

OCI pull, lifecycle, interactive exec, logs, events, cgroups v2, overlay filesystems, bridge networking, mounts, image operations, and execution-policy checks form the production reference path.

Typed control plane

The mbx CLI, policy-gated MCP server, Crux JSON-RPC plugin, and read-only TUI converge on the daemon protocol.

Shipped

Platform suites

GKE is production-ready for unprivileged pod execution. Colima, smolvm, and krun provide experimental lifecycle paths with explicit capability limits.

Shipped

Standing quality gates

Protocol ownership, handler coverage, adapter evidence, macOS validation, unit tests, and dependency audits remain the promotion bar after the feature freeze was lifted.

Active work

P1

Cross-platform exec and logs

Native Linux has complete exec and historical logs. VM-backed macOS suites can run workloads and stream initial cmt, but cannot yet exec into an existing container.

P1

Linux verification from macOS

The VM test path can exercise image pulls. Native overlay and cgroup scenarios still require a Linux environment with the correct privileges.

P1

Windows composition

winbox remains a stub. Named Pipe transport, authentication, WSL2/HCS backend selection, and helper execution are still required.

P1

Unprivileged isolation

Default capability dropping, user namespaces, UID/GID maps, rootless storage, networking, and cgroup delegation remain open.

Next priorities

P2

Networking rollout

Package CNI plugins, harden mode validation, expand privileged integration coverage, and make installation repeatable.

P2

Image workflow parity

Broaden live-registry coverage, expose the remaining image operations through the CLI, and document adapter-specific build, push, and commit behavior.

P2

Checkpoint implementation

The snapshot protocol and CLI exist, while production suites still compose NoopVmCheckpoint. Real backend support needs explicit lifecycle semantics and tests.

P2

CI coverage closure

Bring Linux-root sandbox and feature-gated CLI subprocess coverage into a dependable CI lane without slowing every pull request.

Dogfooding track

The roadmap is strongest when minibox proves its own product claims through real operator and agent workflows.

Ready

Operator lifecycle drill

Run pull, create, observe, stop, remove, and cleanup through mbx, then correlate state, events, logs, traces, and metrics.

Ready

Policy-gated agent run

Exercise MCP read-only defaults, explicit mutation enablement, high-risk run denial, manifest inspection, and cleanup.

Planned

Image supply-chain round trip

Build, run, commit, push, clear the cache, pull again, and verify workload identity through a disposable registry.

Planned

Sandboxed generated code

Standardize a prebuilt toolchain image or bind-mount workflow around the existing resource-limited sandbox path.

Planned

Restart recovery drill

Restart the daemon around running and paused containers and verify conservative orphan and freezer-state reconciliation.

Planned

Cross-adapter conformance

Run one lifecycle story through native, GKE, Colima, smolvm, and krun while recording expected capability skips.
