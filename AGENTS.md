# AGENTS.md

**Single source of truth for agent guidance in this repository.** `CLAUDE.md` is a
pointer to this file. Everything an agent needs — tooling, gates, architecture
guardrails, security invariants, git workflow, conventions — lives here.

This file is hand-maintained. Portions of `CLAUDE.md` are machine-generated by
godmode and the Claude Code toolbox; those generated blocks stay in `CLAUDE.md`
but must not duplicate rules stated here. **When guidance conflicts, this file
wins.**

## Project Snapshot

Minibox is a Rust 2024 Docker-like container runtime with a daemon/CLI split, OCI
image support, Linux namespace/cgroup isolation, overlay filesystems, and macOS
adapter backends.

Default adapter selection lives in `crates/minibox-core/src/adapter_registry.rs`:
`smolvm` by default, falling back to `native` on Linux or `krun` on macOS when
the `smolvm` binary is absent. Explicit `MINIBOX_ADAPTER=<value>` disables
fallback.

## Environment Rules

- **All Bash tool calls must be `nu -c "..."`.** Bare commands and `bash -c` are both
  blocked by a course-correct hook. In nu, `&&` is `;`, `2>/dev/null` is `| ignore`,
  `$HOME` is `$env.HOME`, and `cmd > f` is `cmd | save -f f`. A parse error anywhere in a
  `;`-chained command aborts the **whole line** — no segment runs and no segment is
  reported — so never chain a destructive or verifying command with a risky one.
- **Never `cd` to change directory.** Use the Bash tool's `workdir` parameter, or
  `git -C <path>` for one-off git calls. `cd` in an orchestration command is blocked.
- **Use the dedicated tools, not shell equivalents**: `Grep`, `Glob`, `Read`, `Edit`.
  `grep`, `ls`, `find`, `cat`, `sed`, and `head`/`tail` are blocked in Bash. The denials
  are loud and name the replacement, but they cost a full reissue each — this is the
  single largest source of wasted tool calls in this repo.
- No vanilla Python: use `uv run` for Python scripts and `uv` for package management.
- Prefer Nushell or Rust for new scripts; if Python is necessary, use a uv script with inline metadata.
- No Python scripts are expected in the project; use Rust scripts or Nushell helpers for agent tooling.
- No emojis in code or docs unless explicitly requested.
- Prefer editing existing files over creating new ones.
- Remove unused code completely; do not comment it out.
- Never commit secrets, credentials, or API keys.
- Fuzz seeds, corpus, and artifacts are gitignored via `**/fuzz/seeds/`,
  `**/fuzz/corpus/`, `**/fuzz/artifacts/`. Do not commit generated fuzz data.

## Scope Discipline

- Do exactly what was asked. Do not escalate a narrow request into a broader sweep
  (e.g. a single-crate fix does not become a workspace-wide refactor; a docs tweak
  does not become a doc audit).
- Never edit global/machine-level config (`~/.config/*`, the user's global
  `~/.claude/CLAUDE.md`, shell rc files) from inside a minibox session without
  explicit confirmation first.
- If a follow-up instruction is ambiguous ("take that line out", "update the config
  too"), ask one targeted clarifying question — naming the specific file or crate —
  before editing, rather than guessing at the referent.

## Verify Before Claiming

- Never assert what a crate, adapter, or dependency does without checking: grep the
  source, run `cargo tree -i <crate>`, or run the binary's `--help`. Do not answer
  from memory about this workspace's own code.
- After implementing, run the actual gate (`cargo xtask verify`, `cargo xtask test
unit`), not just `cargo check`/`cargo build` — see **Gates and Toolchain** below.
  Never report "done" on a change you have not run through the real gate.
- When verifying container code gated `#[cfg(target_os = "linux")]`, use the QEMU
  Linux harness (`rust-script scripts/qemu-linux-tests/run.rs --filter <module>`),
  not a macOS `cargo check` — a green macOS run proves nothing about that code path.

## Pipelines & Multi-Step Work

- Run the complete chain, including the final step, not just the parts that look
  like progress. A godmode phase that ends in SHIP is not done until `godmode
handoff` has actually run and the push has landed — not when the commit is staged.
- Before dispatching a subagent or entering ACT, make sure there is a concrete
  target (a file list, crate name, issue number, or diff range). If none exists,
  ask for one instead of dispatching a vague prompt that a subagent will bounce
  back as ambiguous.
- Do not repeat the same blocked-status report turn after turn. State the blocker
  once, and wait for the user or for the blocking condition to change.

## Gates and Toolchain

Use `cargo xtask` (or `just`) for repeatable gates. Prefer `xtask` over bare
`cargo` — the xtask gate runs steps the bare commands miss.

| When                  | Run                           | Covers                                                                                                                                                                                      |
| --------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before any commit     | `cargo xtask verify`          | fmt check, workspace check, clippy `-D warnings`, feature matrix (18 flag combos), architecture rings, borrow fixtures, docs audit. Read-only; safe on a dirty tree.                        |
| On commit (automatic) | `cargo xtask pre-commit`      | clippy `-D warnings` + architecture on every commit; `cargo fmt --all` and re-stage only when Rust is staged, plus config/docs checks, doc-dates, secret scan. **Never use `--no-verify`.** |
| Before pushing        | `cargo xtask prepush`         | release build, release nextest, conformance. Use `cargo xtask coverage` separately for coverage.                                                                                            |
| Unit tests            | `cargo xtask test unit`       | cross-platform workspace library tests.                                                                                                                                                     |
| Property tests        | `cargo xtask test property`   | property tests.                                                                                                                                                                             |
| Standalone            | `cargo xtask borrow-fixtures` | borrow-reasoning must-pass/must-fail fixtures.                                                                                                                                              |

- **The repo is nextest-based.** Do not substitute bare `cargo test` — use
  `cargo xtask test unit` / `test property`.
- `godmode verify` also exists (nextest + clippy + fmt + non-empty git log).
  `cargo xtask verify` is the canonical gate; do not use both.
- **Bare `cargo check` / `cargo clippy` are not gates.** They pass while skipping
  the feature matrix, architecture rings, and borrow fixtures.

### The `cargo fmt` footgun

`cargo fmt --all` (without `--check`) rewrites **all** workspace `.rs` files
including untracked ones — and therefore any Rust file another writer has
uncommitted changes in. If another writer has uncommitted Rust changes, use
`cargo fmt --all --check` so you do not reformat their work.

## Core Commands

- `cargo check --workspace` — compile/check workspace.
- `cargo xtask nuke-test-state` — clean orphaned containers, overlays, cgroups, temp state.
- `cargo xtask build-test-image` — build cached Alpine kernel/agent image for macOS VM adapters.
- `cargo xtask demo` — showcase binary. Resolution prefers `target/release` over
  `target/debug`; after fixing a bug, rebuild release too or the demo silently runs
  the stale binary.
- `cargo xtask ci-watch [--branch <name>]` — watch latest GHA run with job-level detail; defaults to current branch. Nushell wrapper: `nu scripts/ci-watch.nu`.
- `cargo xtask bench` — run criterion benchmarks, save to `bench/results/`.
- `cargo xtask doctor` — canonical preflight: tool/env checks, secret-manager auth, Linux system caps. Absorbed `scripts/preflight.nu`'s checks; that script is now just the fast SessionStart hook.
- `just test-integration` — Linux+root cgroup tests.
- `just test-e2e` — cross-platform protocol end-to-end tests.
- `just test-system` — Linux+root full-stack daemon/CLI tests.

## Git Workflow

Branches follow the stability pipeline:

`develop` -> `staging` -> `release` -> `main` -> `v*` tag

- `develop` is the default working branch. Feature, hotfix, and chore work
  belongs there; work on it at virtually all times and branch only when a change
  needs isolation.
- Run `git branch --show-current` before every commit. If the answer is `main`, STOP.
- Do not promote `staging` to `release` without confirming `staging` CI is green.
- Do not promote `release` to `main` without confirming `release` CI is green.
- **Never commit unless explicitly asked.**
- Stage explicit paths. Never `git add -A` in a tree another agent may be working
  in, and read `git diff --cached --stat` before committing.
- `.ctx/HANDOFF.*.*.yaml` is gitignored by default; use `git add -f` only when intentionally tracking it.

### Branch Protection

- `main` is protected via GitHub rulesets. All changes land via PR with required
  status checks. Branch must be up-to-date before merge.
- `staging` and `release` block force pushes and deletions; require `CI passed`.
- `release` -> `main` promotion creates a PR automatically via CI.
- Required status checks on `main`: `CI passed`, stability gates, `actionlint`.
- Version bumps must also update `<!-- fact:workspace_version=X.Y.Z -->`
  markers in `docs/core/{ARCHITECTURE,CRATE_INVENTORY}.mbx.md`, or
  `cargo xtask verify`'s docs-audit reports a mismatch.
- If a file listed in `taskit.toml`'s `[[protocol.surfaces]]` is deleted or
  renamed, update the list and run `taskit protocol drift --update` to regenerate
  `taskit-protocol.lock`, or the check breaks.

## Concurrent Writers

A shared working directory is a two-way hazard, not just a commit-sweeping one.
Another agent using the same checkout can also:

- commit to the branch you believe you are on, or check out a different branch
  mid-operation, so your `git merge` silently reports "Already up to date" while
  merging nothing;
- leave uncommitted edits to files you were about to touch.

Before any multi-step git operation, re-read the branch and
`git status --porcelain`. Do not reformat, stage, or commit a file you did not
author — flag it instead. **Isolated worktrees are the fix.**

## Architecture Guardrails

- Domain ports live under `crates/minibox-domain/src/`; `minibox_core::domain`
  and `minibox::domain` are compatibility re-exports of those same types.
- `minibox` re-exports `minibox-core`; do not remove re-exports needed by
  `as_any!`/`adapt!` macro expansion.
- `DaemonRequest`/`DaemonResponse` are canonical in `crates/minibox-core/src/protocol.rs`.
- `DaemonResponse::ContainerOutput` is **non-terminal**; most other response
  variants end request streaming. Update terminal-response logic when adding
  variants, or requests will hang or truncate.
- `HandlerDependencies` changes require updating all adapter suite construction
  sites in `crates/miniboxd/src/main.rs`.
- Protocol changes start in `crates/minibox-core/src/protocol.rs`; update
  handlers, CLI paths, and snapshot tests together.
- New request fields should use `#[serde(default)]` when wire compatibility matters.

## Security Invariants

- Preserve tar extraction protections: reject `..`, absolute symlinks, device nodes, FIFOs, and setuid/setgid bits.
- Keep overlay/path validation inside the target root.
- Preserve native-adapter Unix socket peer credential checks and root-only access.
- Enforce image pull size limits.
- Container init must use `execve` with explicit env, not `execvp`.
- `tar::Builder::append_dir_all` follows symlinks by default. Container rootfs
  layers often contain symlinks that only resolve inside a live mount namespace
  (e.g. Alpine's `etc/mtab -> ../proc/mounts`) — call `.follow_symlinks(false)`
  before tarring an extracted layer/rootfs dir, or it fails with ENOENT on the
  host. See `docker_archive.rs`, `commit.rs`, `push.rs`, `colima_push.rs`.

## Rust and Test Conventions

- Rust edition is 2024. `std::env::set_var` and `remove_var` are unsafe;
  serialize env-mutating tests with a shared lock.
- Treat warnings as errors in clippy runs: use `-D warnings` or the xtask/just gates.
- Gate Linux-only code and imports carefully. macOS `cargo check` does not
  validate `#[cfg(target_os = "linux")]` paths.
- Do not use `Command::cargo_bin()` for subprocess CLI tests; use the existing
  `find_minibox()`/`MINIBOX_TEST_BIN_DIR` pattern.
- Never discard handler channel-send failures with `let _ = ...`; log dropped-client cases.

### Test Daemon Gotchas

- Never use `Stdio::piped()` for daemon stdout/stderr in tests unless you drain
  the pipes in a background thread. Debug logging during slow operations (pull,
  run) can exceed the 64KB OS pipe buffer and deadlock the daemon. Use
  `Stdio::null()` or reduce log level to `warn`/`info`.

## Hook Notes

Claude hook config lives in `.claude/settings.json`. The `SessionStart` hook runs
`nu scripts/preflight.nu`; it should be fast, read-only, and non-fatal so startup
is not blocked by normal local state like an uncommitted working tree.

## Task Graph

Tasks live in `.ctx/godmode/tasks.yaml` (lowercase, gitignored via `.gitignore`
`.ctx/*`). Use `godmode task` CLI for state transitions. Independent chains can
run in parallel via `godmode:parallel-agents`. A task is runnable when all
`depends_on` items are `done`.

**Ignore `.ctx/GODMODE.tasks.yaml`.** That uppercase variant is a stale leftover
(last touched 2026-08-22) the CLI does not read. Reading it shows a larger, wrong
graph. If the two ever disagree, the lowercase path is authoritative.

## Subagent Rules

- Each subagent must run `git branch --show-current` before every commit.
  If the answer is `main`, STOP — do not commit to main directly.
- Never use `--no-verify` on git commits.
- Worktree subagents MUST merge their branch back and remove the worktree
  before reporting done. An orphaned worktree means the task is incomplete.
- After subagents complete, verify their changes were committed
  (`git log --oneline -3`). A HANDOFF with `commits: []` is incomplete.
- Cap parallel subagents at 5 concurrent to avoid API rate limits.
- Parallel subagents editing code MUST use isolated worktrees, not a shared
  checkout — a shared tree lets one agent's commit sweep in another agent's
  uncommitted edits, misattributing content to the wrong commit. The hazard runs
  both ways; see **Concurrent Writers**.
- Don't run parallel `cargo check`/`clippy`/`test` invocations against the same
  `target/` dir — the shared build lock stalls agents for 600s+. Use
  `CARGO_TARGET_DIR` per worktree, or serialize cargo invocations.
- Subagents must not fix unrelated bugs discovered incidentally (e.g. while
  manually testing) outside their assigned scope — file/flag them instead.
  Fixing them risks editing files another concurrent agent owns.
- If tests fail, debug and retry up to 3 times before escalating.

```text

No println!/eprintln! in daemon   → use tracing::info!/warn!
No platform imports in core       → minibox-core has zero OS deps
```
